# 小薇直播纯净版 - MVP 产品设计文档 (PRD)

## 一、 产品定位与背景

### 1.1 背景痛点
对于使用智能电视、电视盒子（如运行“小薇直播”等老牌电视直播软件）的家庭用户与长辈，日常看电视常面临以下核心痛点：
* **源失效极快**：网上搜到的直播源几天甚至几小时就失效，电视频繁出现黑屏卡顿。
* **垃圾广告台泛滥**：列表中充斥着购物台、特惠体验台、导购台，误导长辈。
* **别名混乱重复**：同一个频道因名称各异（如 `CCTV-1`、`CCTV1综合`、`CCTV-1高清[1080P]`）在列表里出现十几个，选择困难。
* **电视端导源门槛高**：每次换源需要找 U 盘、拔插电视或寻找复杂的内网传输工具，无法实现“一次配置、无感自动更新”。

### 1.2 产品定位
**小薇直播纯净版**定位为：**面向电视端（以小薇直播为核心宿主）的高可用、全自动直播源清洗维护与订阅服务**。
系统充当电视软件的“云端/局域网数据源引擎”，负责在后台持续采集、去伪存真、快速探活、智能排序，并对外提供开箱即用的纯净源。

### 1.3 MVP 目标
在当前版本中，用**最小开发成本**跑通完整的**“采集 -> 清洗 -> 测速淘汰 -> 标准导出 -> 电视订阅/分发”**业务闭环，让用户能在电视端看到真正稳定、无广告、秒切台的主流电视频道。

| :--- | :--- | :--- |

## 三、 MVP 功能边界划分 (Scope & Boundary)

为了保证 MVP 快速交付与高稳定性，严格界定“做什么”与“暂不做什么”：

### 3.1 核心功能范围 (In Scope)

1. **主流频道收录与标准化**：
   * 优先聚焦国民度最高的核心频道：**央视频道**（CCTV-1~17、CCTV-4K/8K、CCTV-5+）、**各大省级主流卫视**（湖南、浙江、江苏、东方、北京、广东等）及主要地方综合台。
   * 频道别名归一：消除 `1080P`、`超清`、`HD`、空格等后缀，统一映射为规范标准名。
2. **零容忍广告过滤**：
   * 基于严格黑名单规则过滤“购物、特惠、商城、导购、广告、测试”等非正常节目频道，确保清单 100% 纯净。
3. **轻量自动化测速与线路优选**：
   * 并发 HTTP HEAD/GET 探活机制，秒级剔除已断流或响应超时的死链。
   * **优选截断**：每个频道仅保留响应延迟最低的 **2~3 条最优线路**，彻底告别“一个台几十条卡顿垃圾源”的糟糕体验。
4. **小薇直播专属格式与标准 M3U 双轨输出**：
   * 严格按照小薇直播规范输出带有 `#genre#` 分组标记的 TXT 文件。
   * 同时生成标准扩展 M3U 文件，兼顾其他播放器（如 TiviMate、Kodi、VLC 等）。
5. **常驻订阅服务与下载交付**：
   * 内置轻量 HTTP 接口提供固定的在线订阅链接（如 `/live.txt`），电视端填写一次即可实现自动刷新。
   * 提供前端一键下载与内容复制，便于 U 盘离线导入。
6. **轻量监控大屏与手动触发**：
   * Web 界面实时展示源健康度、频道总数、最后更新时间，并提供“一键立即更新”操作按钮。

### 3.2 明确排除的功能 (Out of Scope / Post-MVP)

* ❌ **自研 Android TV App**：不开发电视播放端，完全借力现有小薇直播生态，避免陷入繁琐的 Android 机顶盒兼容性适配。
* ❌ **重型数据库与用户鉴权体系**：MVP 阶段零数据库依赖，数据采用纯文本及 JSON 存储，面向家庭自用。
* ❌ **深度音视频解码质检**：不做全量视频帧解码、画面冻结或分辨率深度识别，仅做传输层与首包探活，避免过度消耗带宽与算力。
* ❌ **海量海外/小众轮播频道**：暂不收录境外或极度不稳定的个人搭建影视轮播源。

## 四、 核心功能模块规格设计

### 4.1 数据抓取与解析模块 (Fetcher)
* **输入支持**：支持网络远程链接（如优质 GitHub/Gitee 维护源、公网 IPv6/IPv4 源）与本地测试文本。
* **格式兼容**：自动识别并解析标准 M3U 格式及 `#genre#` 分组 TXT 格式。

### 4.2 智能清洗与归一化模块 (Normalizer)
* **广告拦截**：命中过滤词即刻丢弃，不计入后续流转。
* **规则库**：
  * CCTV 正则归纳：`^cctv[-_\s]?(\d+|4k|8k|5\+)` $\rightarrow$ `CCTV-$1`。
  * 卫视正则归纳：提取省份 + `卫视`。
  * 分组归类：央视频道、卫视频道、地方频道、其他频道。

### 4.3 测速探活与排序模块 (Checker)
* **并发控制**：默认 25~30 并发，超时阈值可配（默认 3 秒）。
* **排序与截断算法**：
  1. 按频道分组聚类所有候选 URL；
  2. 剔除无效响应（状态码非 200/206 或连接超时）；
  3. 按响应延迟升序排序；
  4. 截取前 $N$ 条（默认 2~3 条）作为最终输出源。

### 4.4 交付与分发模块 (Exporter & Server)
* **固定路由**：
  * `GET /live.txt`：返回小薇专用格式文本流（`Content-Type: text/plain; charset=utf-8`）。
  * `GET /live.m3u`：返回标准 M3U 播放列表。
  * `GET /api/status`：返回当前系统状态、有效频道数、更新时间。
  * `POST /api/refresh`：后台触发即时重新抓取测速任务。
* **Web UI 控制台**：单页可视化呈现，包含状态卡片、源配置入口、频道清单快速搜索与预览。

## 五、 质量与验收指标

| 维度 | 指标标准 | 验收方式 |
| :--- | :--- | :--- |
| **纯净度** | 最终输出频道中广告台/购物台出现率为 **0%** | 关键词扫描与抽样检查 |
| **可用性** | 最终导出的优选线路可用率 $\ge$ **95%** | 自动化批量探活测试 |
| **精简度** | 单个频道有效线路数控制在 **2~3 条**，无冗余重复链接 | 输出文本行数与结构校验 |
| **兼容性** | 小薇直播能够无报错成功读取 `#genre#` 分类与全部有效频道 | 真机/模拟测试导入验证 |
| **性能** | 单次全量抓取清洗（约 300~500 条源）测速耗时 $\le$ **60 秒** | 批量执行耗时统计 |

## 六、 后续迭代演进路线 (Roadmap)

* **V1.1 (多网络智能适配)**：区分电信、联通、移动与 IPv6 专属路线，提供家庭网络定制化源订阅。
* **V1.2 (Docker 一键部署 & GitHub Actions 自动化)**：提供 Docker 镜像并打通 GitHub Actions 自动每日构建发布到 Pages，实现免本地服务器托管。
* **V1.3 (EPG 节目单与台标集成)**：为 M3U 注入精确电视指南 (EPG) 与高清台标，提升现代播放器体验。
